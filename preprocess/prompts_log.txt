以下是目标中间表示的规范文档：
# 📑 XCPG-IR 规范 v1.0
*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。
------
## 4. XCPG-IR 结构
```yaml
xcpgir_version: "1.0"
rule:
  id: string
  kind: taint | pattern | hybrid | value
  severity: INFO | WARNING | ERROR | CRITICAL
  message: string
scope:
  languages: [java, python, go, js, php, "*"]
  frameworks: ["*"]
  env: { os: [linux, windows], shell: [bash, sh, powershell] }
sources: [...]
sinks: [...]
sanitizers: [...]
barriers: [...]
propagations: [...]
flows: [...]
report: {...}
tests: {...}
```
------
## 5. Match（节点匹配）
所有实体（Source / Sink / Sanitizer / Barrier）都通过 **match** 来定位 CPG 节点。
```yaml
match:
  node: CALL | LITERAL | PARAM | RETURN | FIELD | METHOD
  api:
    package: string
    type: string
    method: string
    signature: ["(...)"]
  type:
    name: string
    match: exact | subtype
  arg_index: int
  where:
    - op: eq | neq | regex | in
      left: 属性名 (value, methodFullName, arg[0].value)
      right: 值
```
------
## 6. 实体定义
### Source
```yaml
sources:
  - id: USER_INPUT
    match:
      node: CALL
      api: { type: javax.servlet.ServletRequest, method: getParameter }
```
### Sink
```yaml
sinks:
  - id: SQL_EXEC
    match:
      node: CALL
      api: { type: java.sql.Statement, method: executeQuery }
      arg_index: 0
```
### Sanitizer
```yaml
sanitizers:
  - id: ESCAPE_HTML
    match: { node: CALL, api: { type: org.apache.commons.lang.StringEscapeUtils, method: escapeHtml } }
    effect: neutralize
    scope: { sinks: [XSS_SINK] }
```
### Barrier
```yaml
barriers:
  - id: RETURN_STOP
    match: { node: RETURN }
    effect: stop
```
### Propagation
```yaml
propagations:
  - id: ARG_TO_PARAM
    edge: arg->param | return | field-store | field-load | array | phi | alias
    kind: taint | value
```
------
## 7. Flow（源到汇路径）
Flow 定义了可能的数据流轨迹，Barrier 在执行时自动剪枝。【这个flow这使用的ID】
```yaml
flows:
  - source: USER_INPUT
    sink: SQL_EXEC
    through: [ARG_TO_PARAM*, RETURN*]
    constraints:
      path:
        must:     [ { pattern: "CALL(java.sql.Statement.executeQuery)" } ]
        must_not: [ { pattern: "CALL(org.owasp.ESAPI.encoder.encodeForSQL)" } ]
```
------
## 8. Sanitizer vs Barrier
| 属性       | Sanitizer                           | Barrier                            |
| ---------- | ----------------------------------- | ---------------------------------- |
| 语义       | 转换 / 净化污点                     | 完全阻断传播                       |
| 结果       | 数据继续流动，但标签改变            | 数据流在此终止                     |
| 示例       | `escapeHtml()`, `Path.toRealPath()` | `return`, `throw`, `System.exit()` |
| 对路径搜索 | 保留边但修改标签                    | 剪枝，路径不再延伸                 |
------
## 9. Report 与 Tests
```yaml
report:
  message: "User input reaches SQL execution without sanitization"
  locations: ["source","sink","path"]
  evidence: { capture: [{ argument: 0 }] }
tests:
  positive:
    - "stmt.executeQuery(request.getParameter("q"));"
  negative:
    - "stmt.executeQuery(ESAPI.encoder().encodeForSQL(request.getParameter("q")));"
```

*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。

------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。

| 属性       | Sanitizer                           | Barrier                            |

# 📑 XCPG-IR 规范 v1.0
*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。

# 📑 XCPG-IR 规范 v1.0
*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。

# 📑 XCPG-IR 规范 v1.0
*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。

## 8. Sanitizer vs Barrier
| 属性       | Sanitizer                           | Barrier                            |

# 📑 XCPG-IR 规范 v1.0
*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。
------

## 5. Match（节点匹配）
所有实体（Source / Sink / Sanitizer / Barrier）都通过 **match** 来定位 CPG 节点。
```yaml
match:
  node: CALL | LITERAL | PARAM | RETURN | FIELD | METHOD
  api:
    package: string
    type: string
    method: string
    signature: ["(...)"]
  type:
    name: string
    match: exact | subtype
  arg_index: int
  where:
    - op: eq | neq | regex | in
      left: 属性名 (value, methodFullName, arg[0].value)
      right: 值
```

## 7. Flow（源到汇路径）
Flow 定义了可能的数据流轨迹，Barrier 在执行时自动剪枝。【这个flow这使用的ID】
```yaml
flows:
  - source: USER_INPUT
    sink: SQL_EXEC
    through: [ARG_TO_PARAM*, RETURN*]
    constraints:
      path:
        must:     [ { pattern: "CALL(java.sql.Statement.executeQuery)" } ]
        must_not: [ { pattern: "CALL(org.owasp.ESAPI.encoder.encodeForSQL)" } ]
```
------
## 8. Sanitizer vs Barrier
| 属性       | Sanitizer                           | Barrier                            |
| ---------- | ----------------------------------- | ---------------------------------- |
| 语义       | 转换 / 净化污点                     | 完全阻断传播                       |
| 结果       | 数据继续流动，但标签改变            | 数据流在此终止                     |
| 示例       | `escapeHtml()`, `Path.toRealPath()` | `return`, `throw`, `System.exit()` |
| 对路径搜索 | 保留边但修改标签                    | 剪枝，路径不再延伸                 |
------
## 9. Report 与 Tests
```yaml
report:

  locations: ["source","sink","path"]
  evidence: { capture: [{ argument: 0 }] }

  positive:
    - "stmt.executeQuery(request.getParameter("q"));"
  negative:
    - "stmt.executeQuery(ESAPI.encoder().encodeForSQL(request.getParameter("q")));"
```

- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。
------
## 4. XCPG-IR 结构
```yaml
xcpgir_version: "1.0"
rule:
  id: string
  kind: taint | pattern | hybrid | value
  severity: INFO | WARNING | ERROR | CRITICAL
  message: string
scope:
  languages: [java, python, go, js, php, "*"]
  frameworks: ["*"]
  env: { os: [linux, windows], shell: [bash, sh, powershell] }
sources: [...]
sinks: [...]
sanitizers: [...]
barriers: [...]
propagations: [...]
flows: [...]
report: {...}
tests: {...}
```
------
## 5. Match（节点匹配）
所有实体（Source / Sink / Sanitizer / Barrier）都通过 **match** 来定位 CPG 节点。
```yaml
match:
  node: CALL | LITERAL | PARAM | RETURN | FIELD | METHOD
  api:
    package: string
    type: string
    method: string
    signature: ["(...)"]
  type:
    name: string
    match: exact | subtype
  arg_index: int
  where:
    - op: eq | neq | regex | in
      left: 属性名 (value, methodFullName, arg[0].value)
      right: 值
```
------
## 6. 实体定义
### Source
```yaml
sources:
  - id: USER_INPUT
    match:
      node: CALL
      api: { type: javax.servlet.ServletRequest, method: getParameter }
```
### Sink
```yaml
sinks:
  - id: SQL_EXEC
    match:
      node: CALL
      api: { type: java.sql.Statement, method: executeQuery }
      arg_index: 0
```
### Sanitizer
```yaml
sanitizers:
  - id: ESCAPE_HTML
    match: { node: CALL, api: { type: org.apache.commons.lang.StringEscapeUtils, method: escapeHtml } }
    effect: neutralize
    scope: { sinks: [XSS_SINK] }
```
### Barrier
```yaml
barriers:
  - id: RETURN_STOP
    match: { node: RETURN }
    effect: stop
```
### Propagation
```yaml
propagations:
  - id: ARG_TO_PARAM
    edge: arg->param | return | field-store | field-load | array | phi | alias
    kind: taint | value
```
------
## 7. Flow（源到汇路径）
Flow 定义了可能的数据流轨迹，Barrier 在执行时自动剪枝。【这个flow这使用的ID】
```yaml
flows:
  - source: USER_INPUT
    sink: SQL_EXEC
    through: [ARG_TO_PARAM*, RETURN*]
    constraints:
      path:
        must:     [ { pattern: "CALL(java.sql.Statement.executeQuery)" } ]
        must_not: [ { pattern: "CALL(org.owasp.ESAPI.encoder.encodeForSQL)" } ]
```
------
## 8. Sanitizer vs Barrier
| 属性       | Sanitizer                           | Barrier                            |
| ---------- | ----------------------------------- | ---------------------------------- |
| 语义       | 转换 / 净化污点                     | 完全阻断传播                       |
| 结果       | 数据继续流动，但标签改变            | 数据流在此终止                     |
| 示例       | `escapeHtml()`, `Path.toRealPath()` | `return`, `throw`, `System.exit()` |
| 对路径搜索 | 保留边但修改标签                    | 剪枝，路径不再延伸                 |
------
## 9. Report 与 Tests
```yaml
report:
  message: "User input reaches SQL execution without sanitization"
  locations: ["source","sink","path"]
  evidence: { capture: [{ argument: 0 }] }
tests:
  positive:
    - "stmt.executeQuery(request.getParameter("q"));"
  negative:
    - "stmt.executeQuery(ESAPI.encoder().encodeForSQL(request.getParameter("q")));"
```

*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。

- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。

以下是目标中间表示的规范文档：
# 📑 XCPG-IR 规范 v1.0
*(eXtended Code Property Graph Intermediate Representation)*
------
## 1. 背景与动机
不同 SAST 工具（CodeQL、Semgrep、PMD、GoSec、Bandit 等）规则语言差异大：
- CodeQL → 强调数据流与路径。
- Semgrep → 偏向 AST pattern + 轻量 taint。
- PMD/FindSecBugs → 主要是 API misuse。
- GoSec/ESLint-security → 针对语言特性。
缺点：
- 规则不可复用；
- 无法统一 benchmark；
- 工业界和学术界交流困难。
👉 **XCPG-IR 的目标**：
- 基于 **CPG (Code Property Graph)** 统一抽象；
- 表达 **污点传播、值检查、API misuse**；
- 支持跨语言、跨引擎的规则迁移与共享。
------
## 2. 什么是 CPG
**CPG = AST + CFG + DFG 的融合图**。
 它是静态分析工具（如 Joern、CodeQL）的底层语义模型。
### 2.1 节点类型（Nodes）
| 类别     | Node Kind                                                    | 说明 |
| -------- | ------------------------------------------------------------ | ---- |
| 程序结构 | `FILE`, `NAMESPACE_BLOCK`, `TYPE_DECL`, `METHOD`, `BLOCK`    |      |
| 参数变量 | `METHOD_PARAMETER_IN`, `METHOD_RETURN`, `LOCAL`, `MEMBER`    |      |
| 表达式   | `CALL`, `IDENTIFIER`, `LITERAL`, `FIELD_IDENTIFIER`, `ASSIGNMENT`, `RETURN` |      |
| 控制流   | `CONTROL_STRUCTURE`, `JUMP_TARGET`                           |      |
| 类型系统 | `TYPE`, `TYPE_ARGUMENT`                                      |      |
| 模块化   | `IMPORT`, `PACKAGE`                                          |      |
### 2.2 边类型（Edges）
| 类别     | Edge Kind                             | 说明 |
| -------- | ------------------------------------- | ---- |
| 语法     | `AST`, `ARGUMENT`, `RECEIVER`         |      |
| 控制流   | `CFG`, `CDG`, `DOMINATE`              |      |
| 数据流   | `DFG`, `REACHING_DEF`, `PHI`, `ALIAS` |      |
| 调用图   | `CALL`, `REF`, `BINDS_TO`             |      |
| 类型关系 | `EVAL_TYPE`, `INHERITS_FROM`          |      |
| 特殊     | `CAPTURED_BY`（闭包捕获）             |      |
👉 **意义**：
- Source/Sink 对应 **CPG 节点**；
- 传播 Propagation 对应 **CPG 边**；
- Flow 约束对应 **路径模式 (CFG+DFG)**。
------
## 3. 什么是 XCPG
**XCPG = eXtended CPG**，在原始 CPG 的基础上扩展：
- 引入 **跨语言统一 API 签名**；
- 定义 **污点标签体系 (taint kinds)**；
- 明确 **Sanitizer（净化）与 Barrier（阻断）**；
- 增加 **Flow constraints**（must/must_not）用于复杂路径约束；
- 提供可迁移到 **CodeQL / Semgrep / PMD / GoSec** 的抽象层。
